## I. XLSX Generation Integration

The internal XLSX route now:

1. Creates a pending export row.
2. Generates the XLSX bytes once.
3. Uses the generated SHA-256.
4. Writes the exact bytes to artifact storage.
5. Marks the export `generated` with checksum and storage metadata.
6. Returns the same generated bytes to the user.

Unchanged:

- `internal-v2`
- XLSX metadata version `2`
- template SHA-256
- Tax Details mapping
- tax snapshot semantics

## J. PDF Generation Integration

The internal PDF route now follows the same durable-storage flow:

1. Creates a pending PDF export row.
2. Generates the PDF bytes once.
3. Uses the generated SHA-256.
4. Writes the exact bytes to artifact storage.
5. Marks the export `generated` with checksum and storage metadata.
6. Returns the same generated bytes to the user.

Unchanged:

- `internal-pdf-v1`
- PDF metadata version `1`
- Noto Sans font behavior
- PDF content/layout semantics

## K. Checksum / Retrieval Contract

Added checksum support:

- `calculateArtifactSha256(...)`
- `assertArtifactChecksum(...)`
- `getVerifiedArtifactBytes(...)`

`getVerifiedArtifactBytes`:

- rejects historical metadata-only rows with null storage metadata,
- reads exact bytes through `ArtifactStorage.get`,
- recalculates SHA-256,
- throws `ARTIFACT_CHECKSUM_MISMATCH` on mismatch.

## L. Generation Failure Semantics

After Phase 8A, a new export is `generated` only if:

1. artifact generation succeeds,
2. checksum exists,
3. durable storage PUT succeeds,
4. generated-state DB update persists storage metadata.

If artifact storage fails after generation, the export is marked `failed` with sanitized artifact-storage error metadata. The Shipping Note business status is unchanged.

Sanitized artifact error codes:

- `ARTIFACT_STORAGE_NOT_CONFIGURED`
- `ARTIFACT_STORAGE_WRITE_FAILED`
- `ARTIFACT_STORAGE_READ_FAILED`
- `ARTIFACT_CHECKSUM_MISMATCH`

## M. R2 Success / DB Failure Gap

R2 PUT and PostgreSQL commit are not transactionally atomic.

Known deferred gap:

```text
R2 PUT succeeds
DB mark-generated transaction fails
```

Phase 8A does not delete the R2 object as compensation and does not add a reconciliation worker. The deterministic export-ID object key leaves enough identity for future reconciliation.

## N. Drive Lifecycle Foundation
